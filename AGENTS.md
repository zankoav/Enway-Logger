## Формат результата

Сохраняй результат в `logs.json` как JSON-массив:

```json
[
  {
    "date": "dd.mm.yyyy",
    "logs": [
      {
        "message": "text",
        "hours": "1,25"
      }
    ]
  }
]
```

- Для каждого дня создавай или обновляй ровно один объект с полем `date` в формате `dd.mm.yyyy`.
- Поле `hours` — строка с десятичной запятой, например `"1,25"`.
- Сумма `hours` всех элементов одного дня должна быть **ровно `8,00` часов**.
- Не смешивай несколько дней в одном объекте и не создавай дублирующиеся записи для одной даты.
- Одна запись `logs` описывает одну завершённую активность для одной задачи. Для разных задач или активностей создавай отдельные элементы.
- Сначала добавляй записи о звонках Teams, затем записи о работе из коммитов.

## Требования к сообщениям

- Все `message` пиши только на английском языке.
- Используй прошедшее время и описывай завершённый результат: `Implemented`, `Updated`, `Reviewed`, `Tested`, `Investigated`, `Participated`.
- Пиши короткими, грамматически корректными предложениями, понятными заказчику.
- При наличии идентификатора задачи начинай запись с него: `TASK-123 — Implemented Apex validation logic and updated the Flow.`
- Описывай конкретную работу и результат, а не намерение или общее название активности.
- Для встреч указывай участие и цель/контекст: `Status Calls — Participated in Sprint Daily meeting.`
- Если коммитов нет, для задачи из Jira `IN PROGRESS` используй конкретную запись о подготовке или требованиях, например: `TASK-123 — Reviewed implementation requirements for the payment validation update.`

## Запрещённые формулировки

- Не используй расплывчатые сообщения: `Daily`, `Meetings`, `Code review`, `Regression testing`, `Worked on LWC`, `Developed Apex`.
- Не пиши про попытки или незавершённую работу: `Started implementing the feature`, `Started to create unit tests`.
- Не объединяй несколько задач или активностей в одну запись.
- Не используй внутренние сокращения, сложные фразы и лишние технические детали, непонятные заказчику.
- Не ограничивайся названием действия: уточняй, что именно было реализовано, проверено, исправлено, рассмотрено или обсуждено.

## Проверка перед сохранением

- Проверь валидность JSON.
- Проверь, что дата имеет формат `dd.mm.yyyy`.
- Проверь, что каждая запись относится к одной активности и написана на английском языке в прошедшем времени.
- Проверь, что итог часов за каждый день равен ровно `8,00`.
